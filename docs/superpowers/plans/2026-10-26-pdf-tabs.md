# PDF tabs implementation plan

**Goal:** Open each PDF in a switchable, closable tab and restore the session on startup.

**Architecture:** Keep loaded PDF.js documents in a frontend tab list and reuse the existing renderer. Extend native settings with open paths and the active path; native file access remains restricted to picker-selected or saved session paths. Keep legacy last-PDF settings readable.

**Scope:** `src/main.js`, `src/settings.js`, `index.html`, `src/style.css`, native PDF/settings commands and registration, and frontend/native tests. No new dependencies. Existing provider settings, fullscreen, AI context isolation, and settings error handling must remain intact.

- [x] Add regression tests for independent tab positions, close behavior, restoration, and native persistence/validation; observe failure.
- [x] Extend settings/native session authorization and restoration to multiple paths.
- [x] Add tabs and integrate switching, closing, position saving, startup restoration, and shutdown flushing.
- [x] Run the project tests through `test_runner`, fix failures, and review the diff.

**Behavior:** Hide the tab strip below two tabs. Duplicate opens activate the existing tab. Closing the active tab selects its neighbor; closing the last tab leaves the empty reader. Restore other tabs when one PDF is unavailable, and report the unavailable file. Retain the existing startup preference, relabeled for all open PDFs. Save page, scroll, and zoom for each document; flush pending settings before desktop close.

**Verification:** Test runner passed 25 JavaScript unit tests, 27 Playwright tests, 23 Rust integration tests, the frontend build, and the desktop Rust check. Read-only review found a shutdown save-failure trap; fixed with a notice and a second-close exit, covered by the browser tests. Native GUI was not manually launched.
